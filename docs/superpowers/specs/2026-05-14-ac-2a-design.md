## 1. Problem

`src/emhass/static/data/param_definitions.json` carries 87 parameter entries across six categories. Units are currently embedded as free-text inside the `Description` field — parse-feindlich for any downstream tool that needs structured metadata: openapi.json generation, Pydantic auto-gen, AI-readable schemas, automated validators.

Issue #826 requests a structured `"unit": "<value>"` field per entry. Schema audit `audits/2026-04-28-param-definitions.md` §5 already produced a per-entry recommended unit value using a fixed enum, with rationale citing existing Description text. All 87 entries have a unit assignment; no `[REVIEW]` flags.

## 2. Goal

Adopt audit §5 1:1 — add `"unit": "<value>"` next to `default_value` on every entry. Backward-compatible additive change (consumers using `entry.get("unit")` get `None` for un-migrated entries; this PR fills all 87 in one pass so no entry stays un-migrated).

## 5. Concrete edits

For each of the 87 entries, insert `"unit": "<value-from-audit-§5>"` immediately after the `"default_value"` line.

Example — `optimization_time_step` (System):

```json
"optimization_time_step": {
  "friendly_name": "Optimization time step",
  "Description": "The time step of the optimization, in minutes (e.g. 30).",
  "input": "int",
  "default_value": 30,
  "unit": "min"
}
```

Unit-distribution (from audit §5 counts):

| Unit | Count | Notable categories |
|------|------:|--------------------|
| `none` | 39 | Booleans, sensor-IDs, enum-selects, strings, + `set_deferrable_startup_penalty` (dimensionless multiplier per `optimization.py:984`, revised 2026-05-15) |
| `W` | 8 | inverter power, deferrable-load power, battery power |
| `fraction` | 10 | efficiencies, SOC limits, dynamic ratios, mip-gap |
| `¤/kWh` | 7 | tariffs, stress-costs, weights (`€/kWh` pre-PR-#850-review) |
| `count` | 7 | integer counts (modules, segments, ports, threads) |
| `h` | 3 | hours-based durations |
| `°` | 4 | angles |
| `min` | 2 | time-step + cache-age |
| `days` | 2 | retrieval window, forecast horizon |
| `timesteps` | 2 | start/end deferrable-load timesteps |
| `Wh` | 1 | battery_nominal_energy_capacity |
| `s` | 1 | lp_solver_timeout |
| `°C` | 0 | (no temperature params in 87) |
| `€` | 0 | (currency-only entries; tariffs all per-kWh) |
| `%` | 0 | (all percent-like values use `fraction` per audit decision) |
| `kWh` | 0 | (energy params expressed in Wh) |

Total: 87. ✓

## 6. Test strategy

- **JSON validity:** existing pre-commit + CI catches malformed JSON. No new test needed.
- **Schema parsability spot-check:** `python -c "import json; json.load(open('src/emhass/static/data/param_definitions.json'))"` runs clean.
- **Entry-count invariant:** `python -c "import json; d=json.load(open('src/emhass/static/data/param_definitions.json')); print(sum(len(v) for v in d.values()))"` returns 87 (unchanged).
- **Unit-coverage check:** `python -c "import json; d=json.load(open('src/emhass/static/data/param_definitions.json')); missing=[(c,k) for c,sec in d.items() for k,v in sec.items() if 'unit' not in v]; print('missing unit:', missing)"` returns `missing unit: []`.
- **Enum-discipline check:** `python -c "import json; ALLOWED={'W','Wh','kWh','¤/kWh','€','%','fraction','°C','°','min','h','days','timesteps','count','s','none'}; d=json.load(open('src/emhass/static/data/param_definitions.json')); bad=[(c,k,v['unit']) for c,sec in d.items() for k,v in sec.items() if v.get('unit') not in ALLOWED]; print('off-enum:', bad)"` returns `off-enum: []`.
- **Sphinx build optional** — schema doesn't ship in rendered docs, so no impact expected. Run if doc workflow exists to be safe.
