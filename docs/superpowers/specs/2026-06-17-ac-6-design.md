# AC-6 — GET /api/v1/plan structured plan output — Design

**Card:** `AC-6` (board/items.json)

## 1. Problem

EMHASS computes a full optimization result (`opt_res`, a DataFrame whose columns are the
versioned schema in `docs/plan_output_schema.md`, #835) but returns no structured plan over
HTTP. `/action/*` returns a plain-text ack; the schedule only reaches consumers via the Home
Assistant publish or `opt_res_latest.csv` (synthesis F11: `opt_res` is computed in the action
handler then discarded). Any consumer that wants the plan back has to scrape HA entities or
parse the CSV. This is the one EMHASS-core gap blocking the external registry sidecar
(RFC 0001) and the EV-coupling glue that the maintainer and production users are already
building (David's #824 "State Override Bridge" reads the schedule from a HA sensor;
LesIT1 / scruysberghs run the same EMHASS-master + glue pattern).

## 2. Goal

Add a read-only `GET /api/v1/plan` that returns the latest optimization result as
machine-readable JSON plus a schema version. This is the single EMHASS-core ask from
RFC 0001; the core stays stateless and recommend-only.

## 3. Decisions

| # | Decision | Source |
|---|----------|--------|
| D1 | New read-only endpoint `GET /api/v1/plan` under the existing `/api/v1` namespace, consistent with `/api/v1/last-run`. | RFC 0001 §API; synthesis N1 |
| D2 | **Serve via a JSON snapshot written at optim-completion.** Write `plan_latest.json` (records + `generated_at` + `emhass_schema_version`) into `data_path` via atomic temp-file + rename, **inside `_record_optim_snapshot` (`command_line.py`)** — the helper that already persists the `last_run` record after every optim wrapper (perfect / dayahead / naive-mpc, call sites ~1413/1627/1729). The GET reads that file. Chosen over in-memory (breaks across multi-worker/multi-process servers) and over re-parsing `opt_res_latest.csv` (loses dtype fidelity, re-applies schema). **Not** in the publish-data path — that is a separate, optional action that re-reads the CSV (`_load_opt_res_latest`) and is decoupled from the run timestamp. | This design review (2026-06-17); mirrors #851 `last_run` |
| D3 | Response columns follow `docs/plan_output_schema.md` (#835); `emhass_schema_version` carries `EMHASS_SCHEMA_VERSION`. | #835 |
| D3a | Response carries a **`generated_at`** ISO-8601 timestamp = the instant the optimization that produced this plan completed. Without it a consumer can't tell plan freshness or correlate the plan to a run — the sidecar/glue need this to know whether the plan already reflects their latest submission. | Codex review 2026-06-17; mirrors #851 last-run `timestamp` |
| D3b | **Single shared timestamp source, via `last_run.record`'s return.** `generated_at` MUST be the *same value* the `last_run` record stores as `timestamp`. Today `last_run.record()` computes that timestamp internally (`datetime.now(UTC)`, last_run.py ~line 93), returns `None`, and accepts no timestamp arg; `_record_optim_snapshot` only holds `t0_monotonic` (a monotonic float, not a wall-clock instant). So a "capture once, pass to both" approach is NOT implementable as-is. **Mechanism:** change `last_run.record()` to **return** the ISO timestamp string it stamped (was `None`; backward-compatible — existing callers ignore the return). `_record_optim_snapshot` captures that return value and passes it to the plan-snapshot writer as `generated_at`. One clock, computed once in `record`, reused — guaranteed equal across both endpoints. | Codex review 2026-06-17 |
| D4 | Cold-start (no run yet) returns a no-run discriminator mirroring `/api/v1/last-run`'s `status:"no-run"` shape, not a 404. | #851 last-run.schema.json |
| D4a | **The plan snapshot is written only for successful runs** — the write in `_record_optim_snapshot` is gated on `optim_status == "Optimal"` (the exact criterion `last_run` uses to report `"ok"`). Invariant: **`/api/v1/plan` publishes iff `/api/v1/last-run` is `"ok"`.** An infeasible / empty / `Unknown` run does NOT overwrite the snapshot, so `/plan` keeps serving the last VALID plan (or the no-run discriminator if none yet); it never exposes an `infeasible`/`error` verdict — consumers read `/api/v1/last-run` for run outcome. Without the gate, a failed run published a plan while `/last-run` reported failure for the same run, contradicting the "endpoints agree" goal. | Ultracode review F1 (fork session 2026-06-26), commit `46a8838`; regression test `test_record_optim_snapshot_skips_plan_on_non_optimal` |
| D5 | Add `docs/api/v1/plan.schema.json` (response schema, mirrors `last-run.schema.json`); register it as an input in `scripts/generate_openapi.py`; extend the `prek.toml` `generate-openapi` hook `files` regex so the committed `openapi.json` regenerates when the plan schema changes. | #921 / #951 openapi pattern |
| D6 | Read-only, additive, non-breaking. `/action/*`, HA publish, and `opt_res_latest.csv` paths are unchanged. Core gains no state (the snapshot is a derived artifact, like the CSV). | RFC 0001 (stateless core) |

## 4. Files touched

- `src/emhass/web_server.py` — add the `GET /api/v1/plan` route (reads the snapshot, returns JSON or the no-run discriminator).
- `src/emhass/command_line.py` — extend `_record_optim_snapshot` (the helper at ~line 43 that already calls `last_run.record(...)` with the run's `_t0` after perfect/dayahead/naive-mpc optims) to ALSO write `plan_latest.json`, reusing the same timestamp it gives `last_run`. The serializer (`opt_res` → records + `generated_at` + `emhass_schema_version`, atomic write) lives in a small helper; placement per AGENTS.md (mirror the `last_run` module as a sibling), fork session decides surgically. Single optim-completion point — NOT the publish-data path.
- `src/emhass/last_run.py` — change `record()` to **return** the ISO timestamp string it stamps (currently returns `None`; existing callers ignore the return, so backward-compatible). This is the single-source value `_record_optim_snapshot` forwards as `generated_at` (D3b).
- `docs/api/v1/plan.schema.json` — new response schema (mirror `docs/api/v1/last-run.schema.json`).
- `scripts/generate_openapi.py` — register `plan.schema.json` as a schema input + emit the `/api/v1/plan` path.
- `prek.toml` — add `docs/api/v1/plan.schema.json` to the `generate-openapi` hook trigger regex.
- `src/emhass/static/openapi.json` — regenerated (by the hook), committed.
- `tests/` — new tests (see §6).
- Docs — a short entry for the endpoint where the API/`/api/v1` surface is documented (if such a page exists; mirror how `last-run` is documented).

## 5. Concrete edits

The plan (writing-plans) details exact code per task. High level:

1. Snapshot writer: `opt_res` (DataFrame) → `{"emhass_schema_version": EMHASS_SCHEMA_VERSION, "generated_at": "<ISO-8601 run instant>", "plan": [<records>]}`; atomic temp+rename into `data_path/plan_latest.json`. Call it from `_record_optim_snapshot` (command_line.py), right where `last_run.record(...)` is already invoked after each optim — NOT the publish-data path. **Gated on `optim_status == "Optimal"` (D4a): failed/infeasible runs skip the write, so `/plan` stays consistent with `/last-run`.** `last_run.record()` is changed to **return** the ISO timestamp it stamps; `_record_optim_snapshot` passes that return value into the writer as `generated_at` (D3b). The writer never calls `now()` itself, so the two endpoints are guaranteed equal.
2. Route: `GET /api/v1/plan` reads `plan_latest.json`; if absent → no-run discriminator; else returns it. No input params.
3. `plan.schema.json`: response shape (`emhass_schema_version` + `generated_at` + `plan` records + no-run discriminator), mirroring `last-run.schema.json`.
4. openapi: register schema input + path; regenerate `openapi.json` via the hook.

## 6. Test strategy

- Snapshot writer unit test: a known `opt_res` fixture → expected records + `emhass_schema_version`; atomic write produces a valid JSON file.
- Endpoint test: (a) cold-start before any run → no-run discriminator; (b) after writing a snapshot → returns the records with `emhass_schema_version` and `generated_at`; (c) columns present match `plan_output_schema.md`; (d) `generated_at` equals the run instant (agrees with `/api/v1/last-run`).
- openapi: the existing `test_committed_matches_generated` (test_openapi) must still pass after regeneration with the new schema input.
- Follow the existing test layout/patterns; mirror `tests/test_openapi.py` and any `last-run` endpoint test. Per AGENTS.md verify-before-done: run the test suite + `pre-commit`/`prek` before declaring done.

## 7. Acceptance criteria

- `GET /api/v1/plan` returns JSON containing `emhass_schema_version`, a `generated_at` ISO-8601 timestamp matching the run (agrees with `/api/v1/last-run`), and plan records matching `plan_output_schema.md` after an optimization has run.
- Before any run, it returns the no-run discriminator (mirrors `/api/v1/last-run`), not a 500/404.
- A non-Optimal run (infeasible/empty/`Unknown`) does not overwrite the snapshot: `/plan` keeps the last valid plan (or no-run) and never reports `infeasible`/`error`; `/plan` publishes iff `/last-run` is `"ok"` (D4a).
- Snapshot is filesystem-based → consistent across multi-worker/multi-process servers.
- `openapi.json` includes the `/api/v1/plan` path and regenerates cleanly via the prek hook (`test_committed_matches_generated` green).
- `/action/*`, HA publish, and `opt_res_latest.csv` behavior unchanged; no new runtime dependency; default config still works.
- Test suite + prek hooks pass.
