## 1. Problem

EMHASS runs as a long-lived container (Add-on / standalone Docker) but exposes no
machine-readable liveness/readiness surface. A container watchdog (Docker `HEALTHCHECK`,
k8s probe, HA add-on supervisor, or an LLM agent introspecting the deployment) currently
has to scrape the HTML index or parse logs to tell whether EMHASS is up and running on
schedule. The existing `/api/v1/last-run` endpoint (#851, AC-3) reports the *correctness*
of the most recent optimization but is an always-200 envelope — it deliberately does not
answer "should the orchestrator consider this container healthy?" via an HTTP status code.

## 2. Goal

Add a read-only, unauthenticated `GET /healthz` route that answers liveness + readiness
with an HTTP status code a watchdog can act on (200 healthy / 503 not-ready), while
exposing boot timestamp, last-run timestamp/status, and a minimal version block for
diagnostics. Container correctness (an infeasible or errored solve) is explicitly NOT a
health signal — that stays the domain of `/api/v1/last-run`.

## 3. Decisions

Locked via brainstorming session 2026-05-29. Routing flagged four open contract questions
(auth, degraded-vs-down semantics, boot_ts capture, version surface); all resolved here.

| # | Decision | Source |
|---|----------|--------|
| **1 — Status contract** | **Readiness with HTTP 200/503 split, recency-only.** `200 status:"ok"` when ready; `503 status:"degraded"` when not. Last-run *correctness* (`infeasible`/`error`) does NOT flip the health verdict — an infeasible solve is still a healthy server. The raw last-run result is surfaced in-body as `last_run_status` for diagnostics only. `"down"` from the card schema is dropped: a responding endpoint cannot self-report `down`; absence of an HTTP response IS `down`, observed by the watchdog as connection-refused/timeout. Documented, never emitted in-body. | brainstorm Q2; card body was internally inconsistent (`ok\|degraded\|down` vs the existing `ok\|infeasible\|error\|no-run` vocab) |
| **2 — Auth** | **Unauthenticated**, matching every existing route. EMHASS web_server has no auth primitive on master (no `getpass` / `Authorization` / `abort` / header check anywhere); the card's "same gating as `/get-config`" resolves to *no gate* because `/get-config` itself is ungated. The sibling `/api/v1/last-run` is also unauthenticated. Read-only, no sensitive data. | brainstorm Q1; live-master grep 2026-05-29 |
| **3 — boot_ts capture** | **Captured in `before_serving()` as the first statement, before the existing `try` block**, so it is always set even when `initialize()` fails (the handler wraps init in try/except and continues serving). Stored in `app.config["boot_ts"]` as ISO-8601 UTC with `Z` suffix, identical formatting to `last_run` snapshot timestamps. | brainstorm Q3; `web_server.py:before_serving` L83 |
| **4 — Version surface** | **Minimal: `{emhass, python, schema_version}`.** Reuse `last_run.emhass_version()` (returns version or `'unknown'`), `platform.python_version()`, and `EMHASS_SCHEMA_VERSION`. cvxpy and the MILP solver lib are dropped — diagnostic-only, add import/detection fragility (solver is chosen at runtime from config; version introspection differs per backend). | brainstorm Q4; YAGNI |
| **5 — Threshold semantics** | **No `?max_age_seconds` → readiness = "any run ever completed"** (`last_run.read()` is `None` → 503; otherwise → 200). **`?max_age_seconds=N` → `last_run.is_recent(data_path, N)` gate.** EMHASS never guesses a staleness threshold (user run-cadence ranges from 5-min MPC to daily); the watchdog, which knows its own cadence, opts into staleness checking by supplying `N`. | brainstorm Q2 refinement |
| **6 — Invalid `?max_age_seconds`** | **Graceful-ignore → fall back to the existence check (no 400).** A health endpoint returning 400 reads as "unhealthy" to watchdogs that only distinguish 2xx from non-2xx, causing a false restart. A malformed threshold is the caller's bug; the safe failure mode for a liveness probe is to answer the liveness question it can answer. Matches the codebase's defensive-coercion posture (the `_cast_bool` / #876-family work). Logged at debug. | brainstorm sub-point (a) |
| **7 — Code structure** | **Inline handler in `web_server.py` + a module-level pure helper `_health_verdict(snap, max_age_seconds) -> tuple[str, int]`.** Mirrors the sibling `/api/v1/last-run` house style (inline, just merged by the maintainer) rather than a separate `health.py` module. The pure helper isolates the branchy verdict logic (no-run / stale / ok) for clean unit tests without a request context; route-level tests via `test_client` cover the wiring. | brainstorm code-structure choice; consistency with #851 |
| **8 — `schema_version` key name** | Versions block uses **`schema_version`** (not `schema`) to align vocabulary with the sibling's top-level `schema_version` field. Consistency over brevity for a public contract. | brainstorm sub-point (b) |
| **9 — JSON Schema doc** | **Ship `docs/api/healthz.schema.json`** (JSON Schema draft 2020-12), mirroring the sibling's `docs/api/v1/last-run.schema.json`. Directly serves the LLM-ready goal (machine-readable contract). FLAGGED at the spec-review gate as an addition beyond the verbally-approved design — drop if the user prefers minimal scope. | LLM-ready goal-fit; #851 precedent |

## 5. Concrete edits

Single logical change; one commit is fine (maintainer squash-merges).

### a. `before_serving()` (~L83) — boot timestamp
Add as the **first** statement, before the `try`:
```python
app.config["boot_ts"] = datetime.now(UTC).isoformat(timespec="seconds").replace("+00:00", "Z")
```
Add `import platform` and `from datetime import UTC, datetime` to the import block if absent
(fork-session confirms against master — `last_run.py` already uses this datetime idiom).

### b. Module-level pure verdict helper
The handler computes recency via `last_run.is_recent` (so no timestamp-parsing logic is
duplicated) and passes a precomputed `stale` boolean into a pure verdict function. This
keeps all three branches — no-run / stale / ok — unit-testable without a request context
and without a real clock:
```python
def _health_verdict(has_run: bool, stale: bool) -> tuple[str, int]:
    """Map run-existence + staleness to (status, http_code). Recency-only:
    last-run correctness (infeasible/error) does not affect health."""
    if not has_run:
        return "degraded", 503        # no run has ever completed
    if stale:
        return "degraded", 503        # a run exists but is older than the requested window
    return "ok", 200
```
The handler builds the two booleans:
```python
snap = last_run.read(emhass_conf["data_path"])
has_run = snap is not None
stale = (
    max_age is not None
    and has_run
    and not last_run.is_recent(emhass_conf["data_path"], max_age)
)
status, code = _health_verdict(has_run, stale)
```

### c. `GET /healthz` handler (placed next to `/api/v1/last-run`, ~L660)
```python
@app.route("/healthz", methods=["GET"])
async def healthz():
    raw = request.args.get("max_age_seconds")
    try:
        max_age = int(raw) if raw is not None else None
    except (TypeError, ValueError):
        max_age = None  # graceful-ignore per Decision #6
    snap = last_run.read(emhass_conf["data_path"])
    has_run = snap is not None
    stale = (
        max_age is not None
        and has_run
        and not last_run.is_recent(emhass_conf["data_path"], max_age)
    )
    status, code = _health_verdict(has_run, stale)
    body = {
        "status": status,
        "boot_ts": app.config.get("boot_ts"),
        "last_run_ts": snap.get("timestamp") if snap else None,
        "last_run_status": snap.get("status") if snap else None,
        "versions": {
            "emhass": last_run.emhass_version(),
            "python": platform.python_version(),
            "schema_version": EMHASS_SCHEMA_VERSION,
        },
    }
    response = await make_response(orjson.dumps(body), code)
    response.headers["Content-Type"] = "application/json"
    response.headers["Cache-Control"] = "no-store"
    return response
```

### d. Response body — HTTP 200 example
```json
{
  "status": "ok",
  "boot_ts": "2026-05-29T08:00:00Z",
  "last_run_ts": "2026-05-29T09:55:00Z",
  "last_run_status": "infeasible",
  "versions": {"emhass": "0.17.5", "python": "3.12.3", "schema_version": "1.0"}
}
```
HTTP 503 (no run yet / stale): `status:"degraded"`, `last_run_ts`/`last_run_status` `null`
when no run.

## 6. Test strategy

TDD per `superpowers:test-driven-development`. Tests mirror the existing
`tests/test_web_server.py` idiom: `IsolatedAsyncioTestCase`, `web_server.app.test_client()`,
`await client.get("/healthz")`, `@patch("emhass.web_server.last_run.read", ...)`,
`assertEqual(response.status_code, ...)`.

1. Write all tests first against current master; confirm red (route 404 before the route exists).
2. Implement edits a–c; tests go green.
3. Full `pytest` passes.
4. `python -m ruff format --check` clean on new + touched files (no `uvx` on this machine — `python -m ruff`).

Cases:
- **ok / any run** — `read` returns a recent snapshot → 200, `status:"ok"`.
- **no-run** — `read` returns `None` → 503, `status:"degraded"`, `last_run_ts`/`last_run_status` null.
- **stale** — `read` returns an old-timestamp snapshot + `?max_age_seconds=` small → 503, `status:"degraded"`.
- **fresh with threshold** — old snapshot but `?max_age_seconds=` large → 200.
- **correctness-passthrough** — `read` returns `status:"infeasible"` snapshot, no `max_age` → **200** (`status:"ok"`) with `last_run_status:"infeasible"` in body (proves correctness ≠ health).
- **invalid threshold** — `?max_age_seconds=abc` → graceful-ignore → existence check (200 when a run exists), no 400/500.
- **versions block** — keys `emhass`/`python`/`schema_version` present.
- **headers** — `Cache-Control: no-store`, `Content-Type: application/json`.

- All test cases above red on master (404), green after the implementation.

- `python -m ruff format --check` clean for new + touched files.

- `boot_ts` is set even if `initialize()` raises (capture precedes the try).

- `emhass-pr-reviewer` pass from main session; AGENTS.md §3/§5/§6 compliant.

## 8. Out of scope

- cvxpy / MILP-solver versions in the body (Decision #4 — diagnostic-only, import fragility).
- Any auth / gating (Decision #2 — no auth primitive exists; out of scope to introduce one).
- A persisted boot history or uptime counter (single `boot_ts` only).
- A configurable default staleness threshold (Decision #5 — no default; opt-in via query param).
- `"down"` as an in-body status (Decision #1 — unobservable from a responding endpoint).
- Wiring `/healthz` into the Docker image `HEALTHCHECK` directive / add-on config — separate follow-up (the endpoint is the prerequisite; the Dockerfile wiring is a distinct PR/issue).
- Prometheus / metrics endpoint — different concern, not requested.
