## 1. Problem

Since v0.17.3, single-constant deferrable loads with a future-only window
(`start_timesteps_of_each_deferrable_load > 0`) are scheduled to start at t=0 instead of
respecting the window. Confirmed by RikBast across v0.17.3 / v0.17.4 / v0.17.5 with
`prediction_horizon=192`, `start_timesteps=37/72`, `end_timesteps=57/92` — both well
inside the horizon, so the horizon-overflow path is ruled out for his case.

Root cause (RCA established in the issue thread, RikBast's data settled the path):

1. `def_current_state` arrives as a list of **strings** (`['False','False','False','False']`) from the config / runtime-params pipeline.
2. The v0.17.3 "currently-running single-constant load → pin to start of horizon" path checks the per-load element with Python truthiness. The non-empty string `'False'` is truthy → the pin fires even though the load is not running.
3. The pin sets `window_mask[:pinned_steps] = 1.0`, opening the window at t=0 → load starts immediately, ignoring `start_timesteps`.
4. Under MPC rolling-window operation (RikBast's setup), the spurious pin on tick N causes the load to actually start. On tick N+1 the real state IS `True`, so the pin re-fires legitimately — the bug self-reinforces across ticks and a single-shot test can hide it.

Same class as #876 / #878 / #879 (already fixed for *some* array params; #901 surfaces the inventory). `def_current_state` slipped through.

A second, independent defect lives in the same mask-builder function: the
horizon-outside-window fallback at `optimization.py:2924`. When a configured window lies
entirely outside the horizon it currently runs `window_mask[:] = 1.0` — "run anywhere"
instead of "can't run here". This is not RikBast's case (his window is inside the
horizon) but it is on the path we are editing, so we fix it in the same PR under a
separate commit (see Decision #3).

## 2. Goal

Stop the single-constant pin firing on a stringly-typed `def_current_state`; the new
tests prove future-windowed deferrables respect `start_timesteps` under both single-shot
and MPC rolling operation; the horizon-outside-window fallback no longer opens the whole
horizon.

2. Implement Commit 1 (coercion). Tests A and B go green. Test C still red.
