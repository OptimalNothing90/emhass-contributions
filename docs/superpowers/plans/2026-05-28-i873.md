  ## Root cause
  `def_current_state` arrives as a list of strings (`['False','False','False','False']`). Non-empty strings are truthy in Python, so the v0.17.3 "currently-running single-constant load → pin to start of horizon" path fires even when the load is not running. The pin sets `window_mask[:pinned_steps] = 1.0`, opening the window at t=0. Under MPC rolling-window the bug self-reinforces (spurious pin → load actually starts → next tick's state IS True → pin re-fires legitimately). Same class as #876 / #878 / #879; `def_current_state` slipped through.

  ## Fix — two separable commits
  **Commit 1** extends the existing #876-family coercion pattern to `def_current_state` and `set_deferrable_load_single_constant`. No layer migration, no architectural refactor — the class-level coercion strategy is deliberately deferred to a follow-up after #901 lands.

  **Commit 2** is a sibling fix in the same mask-builder: a configured window lying entirely outside the horizon should set `window_mask = 0` (cannot run), not `= 1` (run anywhere). Does not affect @RikBast's case but lives on the path we are editing, separated into its own commit so a reviewer can take or revert it independently.

**Reality (upstream/master):** Commit `eea5d25` (merged 2026-05-27, by BrettLynch123, likely part of PR #893) already replaced this fallback with a correct three-case handler:
